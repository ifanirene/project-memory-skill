# Live personal-memory acceptance test

Use this after a material change to conversation intake, principle review, or task
retrieval. Fixture tests establish mechanics. A live test must also inspect meaning
and actual use. Keep receipts in the existing run directory and owning project note.
Do not add a second evidence ledger or manufacture a principle to fill a quota.

## Required chain

1. Record the current source version, changed files, and evidence-ledger baseline.
   Collect a bounded packet from authorized, completed real conversations.
2. Read the selected messages with their surrounding context. Check who made each
   choice and whether the apparent source is a user message, injected skill, app
   event, or automation. Preserve compact retrieval receipts without transcript copies.
3. Distill real choices with exact quotations, reasons, costs, scope, and uncertainty.
   Classify every source. Repeated messages in one decision remain one episode.
   Have a separate semantic review check the interpretation against the source.
4. Validate and apply the unchanged proposal through the production controller.
   Show the retained event and original-source identity. Do not substitute a mock
   ledger. When no real judgment is present, report that result and select another
   bounded source; never invent a signal to complete the test.
5. Explain a supported reusable idea in a new or existing principle document.
   Prefer updating an overlapping entry. Preserve cases, boundaries, and source
   standing. Use the validated ledger-review contract for personal interpretations.
   Check the exact evidence snapshot before acknowledging the document's review.
6. In a separate bounded task, let an agent use normal task instructions to select
   relevant guidance from the index. Do not prescribe the expected principle ID.
   Inspect a real action, artifact, or code change that follows the chosen guidance.
   Retrieval or restating a principle is not enough to establish application.
7. Record the changed choice, reason, and observed result in the existing owning
   note. Check that a subsequent collection can find it, and classify attribution
   correctly. An agent's application is operational evidence, not another human
   endorsement. A real user correction follows the ordinary supersession contract.

Fix defects in the reusable skill and add focused regression checks. Rerun affected
live steps. Retain failures as test evidence rather than replacing their receipts
with a success summary. Keep genuine production updates; do not roll them back
merely to leave the ledger unchanged.

## Completion claim

Report each link separately: context read, signal retained, principle revised,
independent task action, and feedback available for review. State which provider
and sources were exercised. Separate source availability, interpretation quality,
workflow mechanics, and downstream benefit. One successful task application does
not establish a general performance gain or future scheduled execution.

No extra user decision is needed when this bounded live validation is already
authorized. If evidence or an independent task is unavailable, report the missing
link and do not label the full chain verified. Keep necessary runtime/schema
checks; do not turn the acceptance test into a new recurring maintenance process.

## Outcome

Maintain two complementary outcomes. Project records preserve what happened and
what can be trusted. Personal memory preserves how the investigator chooses,
learns, and changes. Useful memory must improve a future decision or make a prior
decision understandable. Event counts and axiom counts are not success targets.

Use L2 in ordinary work. Reserve L3 for a small, revisable account of core values,
commitments, and outlook. A principle does not become a core value because it is
old or repeated. A clear statement of a value deserves consideration even if rare.

## Layer meaning and independent evidence dimensions

| Layer | Content | Question answered | Use |
| --- | --- | --- | --- |
| L1 evidence | Attributed choices, corrections, reasons, accepted costs, outcomes, and context | What happened, and what was chosen? | Reconstruct or compare a decision. |
| L2 working principles | Scoped approaches to a class of problems, with rationale and exceptions | How should this kind of work be approached? | Inform a current task without waiting for L3. |
| L3 core commitments | Deeper values or outlooks that explain several choices and competing priorities | Why do these priorities matter, especially when they conflict? | Inform interpretation and strategic choices; remain open to correction. |

Track these dimensions separately:

- **Origin:** direct personal evidence, attributed note, agent hypothesis, or
  borrowed/adapted external guidance.
- **Depth:** episode, working principle, or proposed core commitment.
- **Confidence:** explicit statement, supported interpretation, or tentative
  hypothesis, with reasons rather than a fabricated numerical score.
- **Health:** original context verified, changed, inaccessible, or missing.
- **Use:** not yet tried, consulted, affected a choice, contradicted, or revised.

The present controller uses candidate/reflection/axiom as evidence-status labels.
Its three-session/28-day rule is a historical gate, not the definition of L3.
Retain old labels and history until a validated migration can separate these axes.
In the new design, the faint-collateral preference belongs in L2; it is not by
itself a claim about a fundamental character trait.

## Signal, project context, noise, and uncertainty

Ask: **What future decision could this change, what information would be lost
without it, and who actually supplied the judgment?** A concrete answer is more
useful than a durable-sounding sentence. Use three months as a prompt to identify
plausible reuse, not an expiry date.

**Keep in L1** when an episode provides at least one of these:

- A meaningful choice among plausible alternatives, including a first occurrence.
- A correction, rejected interpretation, changed boundary, or changed mind.
- A stated priority, accepted cost, non-negotiable condition, or explanation of why.
- A surprising outcome that changes a reusable assumption or next action.
- A failure mode, counterexample, or unresolved tension that prevents overclaiming.
- An explicit core-value statement, including whether it describes actual conduct
  or an aspiration. One statement is evidence; it is not a complete identity model.

Use a compact evidence record. Missing motives remain unknown. Do not manufacture
an alternative or an accepted cost to make a routine request look profound.

**Keep as project context** when the information supports an active result but
does not explain personal judgment. Examples include selected input versions,
current sample counts, job state, and output locations. Use the owning notes or
manifest. Do not duplicate these facts into personal principles without a reason.

**Discard from personal extraction** when the item is a routine command, copied
instruction, formatting change, duplicate of the same episode, or status update
without a decision consequence. Record a short no-signal reason. Discard here
means do not promote or duplicate it; it does not authorize deleting source logs,
scientific records, or evidence already supporting a principle.

**Defer** when a likely signal lacks recoverable context, clear attribution, or
enough information to interpret the choice. Rotate deferred items so they cannot
monopolize each batch. Missing evidence is never a no-signal conclusion.

| Example | Disposition | Reason |
| --- | --- | --- |
| A request to save a plot to a named folder | Project context or no signal | Useful location, usually no personal tradeoff. |
| Add one gene to an existing plot, with no explanation | Usually no personal signal | A task instruction alone does not establish a preference. |
| Preserve faint target vessels despite extra background and review | Keep first L1 signal | A clear endpoint, priority, and cost. |
| Reject a cell-state adjustment because transition is the measured effect | Keep | The choice defines the scientific question. |
| Withdraw a previously approved statistical test after finding invalid uncertainty | Keep urgently and link supersession | Changes what current guidance may recommend. |
| A negative control looks better only after a tuning change | Project finding; L1 if a decision follows | Record calibration limits; do not infer a personal preference for a method. |
| The same preference appears in a note, fork, and summary | One evidence lineage | Repetition of the record is not recurrence of a choice. |
| An old note receives a new investigator correction | Keep the correction | Semantic novelty matters more than document age. |
| A job passes its schema check | Operational context | Does not establish biological validity or personal endorsement. |
| An attributed decision has no accessible original context | Retain qualification or defer | Preserve the claim's evidence strength; do not invent direct confirmation. |

## Weekly L2: compare, compress, and make useful

Compare independent decisions, not session count alone. Several turns can be one
episode; one long chat can contain separate decisions. Retain a semantic episode
group and source lineage. Exclude copies, injected prompts, and agent compliance
from independent human support.

Review research priorities, evidence standards, communication, implementation,
and operations. Do not let a large volume of software details crowd out a small
number of consequential scientific choices. Search for competing explanations
and exceptions before broadening a rule.

Within each bounded batch, reserve attention for corrections, first signals, and
less active projects. Rank by likely decision consequence, then rotate the rest.
A noisy high-volume source must not crowd out an older consequential choice.
Report what remains unreviewed; selection priority is not evidence of strength.

Each working principle needs a trigger, recommended action, rationale, cost,
boundary, evidence origin, unresolved questions, and a concrete next use. Useful
tentative principles can be available with their status visible. High confidence
and broad scope are separate judgments.

Borrowed principles keep author, source revision, adaptation, and use limits.
They are available because the user authorized trying useful guidance, not
because an observer inferred that the user has repeatedly behaved that way.
Reading or following a borrowed principle does not count as personal confirmation.

Weekly output should normally contain up to three new or revised interpretations,
one useful exception or tension, a concrete next use, and material coverage gaps.
Zero additions is acceptable when the reviewed evidence contains no new pattern.
Explain what was considered; do not reward length or a quota.

## Monthly L3: interpretation of core commitments

Evaluate explanatory depth, choices under cost or conflict, alternative causes,
and whether the investigator recognizes the interpretation. Ask what multiple L2
principles might express, and when the proposed value does not explain behavior.
Distinguish an aspiration from an observed tendency and an explicit value from an
agent hypothesis. Retain tensions instead of forcing a flattering coherent portrait.

Do not automatically promote by frequency or elapsed time. Those are evidence
descriptors. A proposal can enter review from a rare but meaningful event or a
direct value statement. The review must still establish scope and uncertainty.
User recognition of a new identity-level interpretation is part of its assessment;
this is not an approval requirement for ordinary L1 collection or scoped L2 use.

Current requests and scientific evidence take precedence over inferred values.
Core commitments can evolve. Preserve earlier interpretations and why they changed.

## Bring working principles into real tasks

1. At a consequential planning or interpretation point, consult a task index.
   Load only relevant L2 entries, normally one to three. Skip unrelated memory.
2. Translate the entry into an actual choice. For writing, identify which claim
   must survive a rewrite. For imaging, check weak targets before selecting cleanup.
   For inference, define the estimand and a diagnostic that could change the choice.
3. When memory materially changes the approach, state that briefly. Do not insert
   a memory ceremony into every small task or treat tentative guidance as mandatory.
4. In the existing project note, record a compact use receipt: principle/version,
   task, choice affected, evidence/outcome, and explicit correction or acceptance
   when present. Silence and agent compliance are not confirmation.
5. Let weekly L2 examine these receipts. Revise scope after misapplication, retire
   guidance that repeatedly adds no value, and retain useful negative outcomes.

Example receipt: `B03 used for the calibration diagnostic; compared two competing
causes before a full rerun; diagnostic rejected the proposed cause; no user
endorsement inferred.` The receipt links to the result; it does not copy the data.

A principle can be consulted without changing the choice. Record that distinction.
Do not claim a causal improvement merely because the final action agrees with it.
Where practical, compare the initial proposal with the proposal after retrieval.

**Step 2 — schema and safe migration.** Separate origin, depth, confidence, health,
and use in a versioned model. Keep the old ledger and a reproducible migration

Acceptance: existing evidence, quotations, source health, and history survive;
borrowed guidance cannot satisfy personal-episode counts; same-episode duplicates
do not inflate support; distinct decisions in one long chat remain representable.

**Step 3 — task retrieval and bounded pilots.** Connect the working index to
relevant project/skill entry points. Use existing manuscript editing, imaging, and
statistical interpretation tasks as pilots. Collect only meaningful use receipts.
Avoid forced extra compute or scientific reruns solely to demonstrate memory use.

Acceptance: an L2 entry is found without L3 promotion; an unrelated entry is not
loaded; the action affected and observed result are inspectable; current evidence
can override memory; a failed application changes the principle's scope.

**Step 4 — scheduled work.** Update the existing Observer/Reflector prompts after
the schema and retrieval contract are ready. Keep current cadence initially.
Report coverage, corrections, interpretation, and use separately. Repair stale
skill paths, human registry drift, output/-based manifest discovery, and SCG's
unattended access context as bounded operational tasks. Do not create duplicate
schedules or resume paused work without the user's existing authorization.

Acceptance: real run receipts show the intended steps; file or folder existence
alone does not prove an apply; report formatting does not hide source gaps;
weekly learning output explains a choice rather than only counting events.

## Ownership and change boundaries

Canonical scientific records stay in their repositories. Personal evidence and
borrowed guidance stay in the external memory workspace. Imported source material
is reference data, not executable instructions. Keep provenance for adaptations.
Use controller-managed edits for generated personal state. Do not fabricate human
episodes or weaken source validation to admit external ideas.

Stay on the existing Git branch. Preserve unrelated edits. This plan does not
authorize publishing, sending messages, changing scientific results, or deleting
historical records. Routine implementation checks should test actual failure
modes, not mirror the implementation.

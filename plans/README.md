## Recommended sequence

- **Independent, start anytime**: 005 and 006 (isolated code + tests; each keeps
  the suite green). Do 006 before 009 — the split moves `memoryctl.py`, so land
  the lock fix in it first.
- **Core track, strictly serial** (all edit the core `SKILL.md` / `bootstrap`):
  001 → 002 → 003 → 004 → 007 → 008 → 009.

Why the split (009) is sequenced **last**: extracting a companion is cleanest
once the core has been deduped (003), gated (004), tiered (007), and
preset-ized (008). Doing it earlier means moving files you're still editing.
If you would rather ship the collector separately sooner, 009 can run right
after 004 + 006 — but expect to re-touch the companion when 007/008 land.

If you can only do a few: **002** is the highest-leverage (it's what makes
"shareable" true), **005** fixes a concrete defect (the skill's own example
fails its own validator), and **004** is the reversible first step toward the
full split.
